# 用这套引擎做 AI 自对弈训练：准备清单

> 本文回答"我想让 AI 自己下棋、用这些棋谱训练它，需要提前准备什么"。
> 前提：引擎、棋谱、样本管线**都已经做好了**（见 `AI优化说明.md` §8.5），
> 所以剩下的工作分三类：**环境**、**数据**、**训练方案**。

---

## 0. 一句话

先别急着装 PyTorch。**按顺序做这四步**，每步都有可验证的产出：

```
① 生成数据（自对弈 → 棋谱 → JSONL 样本）  → 产出 training*.jsonl
② 处理不完全信息（暗子编码 + 红黑对称化）    → 产出可训练的数组
③ 先训价值头，再加策略头                   → 产出 .pt 权重
④ 接回搜索里，用 A/B 自对弈验证变强了吗     → 产出"能打的版本"
```

## 1. 准备工作总览（打勾清单）

### A. 环境（现在就能准备）

| 项 | 要什么 | 说明 |
|---|---|---|
| Python | 3.13（你现在就是） | 引擎只用标准库 + pygame |
| **训练框架** | PyTorch（CPU 版够开始） | `pip install torch --index-url https://download.pytorch.org/whl/cpu`；有 NVIDIA 显卡再装 CUDA 版 |
| 数据处理 | numpy（已有）、可选 pandas | JSONL → 张量 |
| 磁盘 | 至少 10 GB 空闲 | 10 万样本约 300 MB，但中间数组、权重、日志要留余量 |
| 显卡 | **不是必需** | 小网络在 CPU 上也能训；有显卡能把"一天"压到"几小时" |
| 时间 | 见 §3 的时间表 | 数据生成是**串行自对弈**，这是最大的一块时间 |

> ⚠️ 装 PyTorch 会下载约 200 MB~2.5 GB（视版本）。如果只是想先看看效果，
> 建议**先用纯 numpy 训一个逻辑回归式的价值头**（§4.1），一晚上就能出结果，
> 再决定要不要上神经网络。

### B. 数据（要用引擎跑出来）

| 项 | 命令 / 位置 |
|---|---|
| 批量自对弈 + 出样本 | `python _bench\gen_training_data.py --games 1000 --time 0.3` |
| 单盘复盘看质量 | `python Game\record_tool.py analyse <棋谱名> --time 0.8` |
| 人机对局棋谱（混进训练集） | 直接玩就有，`Game\records\*.json` |
| 样本校验 | `python Game\record_tool.py train --all -o all.jsonl`（能跑通即可） |

### C. 方案（先定清楚，否则会白跑）

| 决策 | 建议 | 为什么 |
|---|---|---|
| 先训什么 | **价值头**（预测 `eval_red` / 胜负） | 目标密集、容易收敛，能马上改善叶子评估 |
| 再训什么 | 策略头（预测 `move`，用 `legal_moves` 做掩码） | 目标稀疏，需要更多数据 |
| 输入表示 | 10×9×**通道**（每种棋子一个通道）+ 明暗标记 | 见 §4.0，**千万别把暗子真身喂进去** |
| 训练数据里带 `hidden_truth` 吗 | **绝对不带** | 那等于教模型偷看暗子，实战立刻退化（引擎有测试守着这条线） |
| 怎么验证 | `_bench\ab_selfplay.py` 自对弈 A/B + `record_tool.py analyse` 看失着率 | "感觉变强"不算数 |

## 2. 数据是怎么产生的（这一环已经打通）

```
自对弈（引擎 vs 引擎）
      ↓  每盘一个 JSON 棋谱（含逐手局面快照、点评、引擎评估）
Game/records/selfplay-00001.json
      ↓  record_tool.py train（或 gen_training_data.py 边下边导）
训练样本 JSONL（一行一个局面）
      ↓  你的训练脚本
模型权重
```

**样本字段**（一行一个局面，见 `jieqi/record.py::export_training`）：

| 字段 | 含义 | 训练里怎么用 |
|---|---|---|
| `board` | 10 行紧凑棋盘字符串，`R车*`=红方未翻开的车，`..`=空 | 编码成输入张量 |
| `side` | 这一步轮到谁走 | 决定"从谁的视角看" |
| `move` | 实际走法 `[fr,fc,tr,tc]` | **策略头**的标签 |
| `legal_moves` | 该局面全部合法着法 | 策略输出做**掩码**，只在合法着法里选 |
| `eval_red` | 该手前后的引擎评分（红方视角，厘兵） | **价值头**的标签（先拿这个当目标，比直接用胜负更好训） |
| `value` | 终局胜负（走子方视角，胜 1 / 和 0 / 负 -1） | 价值头的另一个标签（更稀疏） |
| `result` | 棋谱结果 | 分组/过滤用 |
| `comment` | 大模型点评（如果有开） | 可选：做"解释生成"任务，或当噪声过滤 |

### 数据量估算（实测，这台机器）

| 每步思考时间 | 一盘耗时 | 一盘样本 | 10 万样本需要 |
|---|---|---|---|
| 0.15 秒 | 约 8 秒 | 约 55 | **约 4 小时** |
| 0.3 秒 | 约 15 秒 | 约 55 | 约 8 小时 |
| 1.0 秒 | 约 50 秒 | 约 55 | 约 25 小时 |

> 想快：把 `--time` 调到 0.1~0.15、`--samples 1`，用低强度自对弈**先把数据量堆起来**；
> 想要"高质量棋"再单独跑一批 `--time 1.0` 的，两批混着用（低强度覆盖广、高强度质量好）。
> 多核并行：这个脚本是单进程的，想跑满 CPU 就把 `--games` 拆成几份、开几个命令行同时跑
> （各自的 `--seed` 错开、`--skip-existing` 打开），样本最终拼进同一个 jsonl。

## 3. 开工前必须想清楚的三件事

### 3.1 不完全信息：**绝不能把暗子真身当输入**

这是揭棋和普通象棋最大的差别。棋谱里**没有**存暗子真身（见 `record.py` 的说明），
所以默认导出的样本天然是安全的。但如果你为了"打标签方便"用了
`--with-hidden-truth`，样本里会多一个 `hidden_truth` 字段——**训练时不要读它**，
否则模型会学会"看穿暗子"，一上实战（拿不到真身）就废掉。

模型能看到的，只能是：**暗子的摆位身份**（它按什么子走）+ **双方已翻开的子** +
**被吃掉的明子**。这些在 `board` 字符串里都有（`*` 表示未翻开）。

### 3.2 视角对称性：同一局面要能从两边看

建议把每条样本**镜像成两份**（红方视角一份、黑方视角一份：棋盘上下翻转 +
颜色互换 + 走法坐标一起变换）。理由：

* 数据量翻倍，且让模型学会"红黑对称"这个先验；
* 否则模型可能只学会"红方怎么下"，执黑就拉胯。

`side` 字段告诉你这份样本原本该谁走；镜像后在训练时把 `value`/`eval` 取反即可。

### 3.3 标签一致性：`eval_red` 和 `value` 别混用

* `eval_red` 是**引擎当时的评估**，密集但有噪声（尤其低时间控制下）；
* `value` 是**终局胜负**，干净但稀疏（一盘棋只有一个结果）。

建议：**先用 `eval_red` 做回归**（模型学"引擎怎么评估"），
稳定后再用 `value` 做微调（模型学"最终谁赢"）。两个一起加权也可以，
但要先把量纲对齐（`eval_red` 除以 1000 之类，压到 [-1,1]）。

## 4. 三条训练路线（由易到难）

### 4.0 输入编码（三条路线共用）

把 `board` 的 10 行字符串变成张量。**通道式**最省事：

```
形状 (C, 10, 9)，C = 2（红/黑）× 7（兵种）+ 1（是否未翻开）
红车 → 通道(红,车) 置 1
黑卒未翻开 → 通道(黑,卒) 置 1，且"未翻开"通道置 1
```

于是每条样本是一个 `C×10×9` 的小矩阵。写个 20 行的编码函数就够，
**注意暗子要用摆位身份填通道**（`R车*` → 红方"车"通道 + 未翻开通道），
因为它就是按车走的。

### 4.1 路线 A：纯 numpy 逻辑回归式价值头（一晚上见结果，推荐先做这个）

* 目标：`eval_red / 1000` 回归；
* 模型：`score = w · features`（features 可以用"每种棋子的数量差 + 位置差"，
  或者直接把编码矩阵展平）；
* 训练：梯度下降 + 正则，几百行 numpy；
* 用途：**替换或加权引擎的材料/位置评估**，然后自对弈 A/B 看胜率。
* 优点：不用装任何框架，训练几分钟，能立刻验证"这套数据管线有没有价值"。

### 4.2 路线 B：PyTorch 小卷积网（策略 + 价值双头）

```
输入 (C,10,9)
  → 3~6 层 3×3 卷积（64~128 通道，ReLU/BatchNorm）
  → 两个头：
     价值头：全连接到 1 个数（tanh → [-1,1]，走子方视角）
     策略头：全连接到 90×90（或"起点 90 + 终点 90"两个头）
```

关键细节：

* **策略头必须做合法着法掩码**：用样本里的 `legal_moves` 把非法位置的 logits 置 −∞；
  否则模型会输出非法着法（引擎那边虽然会拒绝，但训练信号是错的）；
* 走法编码建议用「起点 90 类 + 终点 90 类」两个 softmax，比 8100 类好训得多；
* 损失：`L = L_value(MSE) + λ · L_policy(交叉熵)`，λ 从 1.0 开始试；
* 训练量级：10 万样本、小网络（<1M 参数）在 CPU 上几小时能过拟合，
  所以**留 10% 做验证集**，看验证损失。

### 4.3 路线 C：网络接进搜索（真正提升棋力的地方）

训练好的网络单独下棋通常**不如**现在的引擎（因为搜索很强）。正经用法是：

1. **价值网当叶子评估**：把 `jieqi/evaluate.py::evaluate` 换成"网络分 + 少量手工项"；
2. **策略网当走法排序**：在 `jieqi/search.py::_order` 里用策略概率排序，
   剪枝效率会明显变好（同样的时间能多搜 1~2 层）；
3. 也可以只做 (2)：改动小、风险低，通常就有收益。

接进去以后**必须**跑：

```powershell
# 新旧引擎自对弈（同一台机器、同样时间）
python _bench\ab_selfplay.py --games 20 --time 0.8 --a-no-cache --a-no-ext
python tools\selfplay.py --red-json "{\"time_limit\":1}" --black-json "{\"time_limit\":1}" --games 20
```

并且在 `_bench\diff_eval.py` 那类**差分测试**里加一条"网络版评估 == 手工版评估"
（在关闭网络时），保证接线没接错。

## 5. 常见坑（都是这套代码里踩过或专门防过的）

| 坑 | 现象 | 防法 |
|---|---|---|
| 用 `hidden_truth` 训练 | 自对弈很强，一遇真人就崩 | 训练脚本里断言样本不含该字段 |
| 策略头不做合法掩码 | 模型老输出非法着法，loss 降不下去 | 用 `legal_moves` 掩码 |
| 只用红方视角 | 执黑明显变弱 | 镜像成两份（§3.2） |
| 拿 `value` 当唯一标签 | 收敛极慢、几乎学不动 | 先回归 `eval_red`（§3.3） |
| 数据全是低强度自对弈 | 棋谱质量差，模型学到坏习惯 | 混入 `--time 1.0` 的高质量对局 |
| 训练集与验证集同源 | 验证损失虚低 | 按**棋谱**划分（同一盘棋不能跨集） |
| 忘了"将帅被吃即终局" | 样本里出现"将已不在盘上"的局面 | 引擎已处理；自己写重放时也要照这个规则 |
| 位棋盘位号 ≠ 格子号 | 自己算特征时下半盘全错 | 见 `AI优化说明.md` §8.6 的警告，用 `bit_to_sq` |
